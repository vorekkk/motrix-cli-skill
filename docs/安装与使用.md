# 安装与使用

## 1. 前置条件

| 项目 | 要求 | 检查方式 |
| --- | --- | --- |
| Node.js | ≥ 22 | `node -v` |
| Motrix CLI | `@motrix/cli`（提供 `motrix` 命令） | `motrix --version` |
| Motrix 实例 | 桌面版运行中，或已配对的远端/无头服务器 | `motrix stats` |

```bash
npm i -g @motrix/cli
motrix --version
motrix list        # 桌面版运行时零配置；退出码 3 表示 bridge 不可达
```

权限问题请用用户可写 prefix，**不要用 `sudo`**：

```bash
npm config set prefix ~/.local
npm i -g @motrix/cli
```

## 2. 安装本 skill

```bash
npm i -g motrix-cli-skill                  # 发布到 npm 之后
motrix-cli-skill install                   # 若 npm 拦下了安装脚本，显式装一次
```

### 从源码安装（发布前 / 离线）

```bash
git clone https://github.com/vorekkk/motrix-cli-skill.git
cd motrix-cli-skill
npm pack                                   # 生成 motrix-cli-skill-0.1.0.tgz
npm i -g ./motrix-cli-skill-0.1.0.tgz
```

`npm i -g .`（在仓库目录内）也可以，但 npm 会把它装成指向仓库的**软链接**：卸载请用
`npm uninstall -g motrix-cli-skill`，并且该软链接会让后续的 git 依赖安装因
`rename` 冲突而失败（`ENOTDIR`）。

> 暂不支持 `npm i -g github:vorekkk/motrix-cli-skill`：npm 11.19 把 git 依赖链接到
> `~/.npm/_cacache/tmp/git-clone*` 后即删除该目录，结果是断链、`motrix-cli-skill` 也不在 PATH 上。
> 这是 npm 的 git 依赖行为，包内无法修复；请用上面的 tarball 方式。

全局安装时 `postinstall` 会自动写入检测到的 agent 目录。关闭自动安装：

```bash
MOTRIX_CLI_SKILL_NO_AUTO_INSTALL=1 npm i -g motrix-cli-skill
npx motrix-cli-skill install         # 需要时再手动执行
```

npm 11.19+ 会对 postinstall 打印 `not yet covered by allowScripts` 提示：该脚本此时仍会运行；
如果本机 npm 配置完全禁止安装脚本，就显式执行 `motrix-cli-skill install`，或
`npm i -g --allow-scripts=motrix-cli-skill motrix-cli-skill`。

## 3. 安装到哪里

```bash
motrix-cli-skill list-targets
# ✓ codex: /Users/<you>/.codex/skills
# ✓ claude: /Users/<you>/.claude/skills
```

规则：

- `--target all`（默认）只写**检测到**的 agent（存在 `~/.codex` / `~/.claude`）；都没检测到则退回 Codex。
- `--target codex|claude` 显式指定；`--target /path/to/skills` 直接写目录。
- Codex 位置优先用 `CODEX_HOME`。
- 两个 skill 名 `motrix-cli` / `motrix-cli-en` 与官方 `motrix` skill 不同名，可共存且互不覆盖。
- 每个目录内有 `.motrix-cli-skill.json` 清单（包名、版本、语言、每个文件的 sha256）。

## 4. 常用命令

```bash
motrix-cli-skill install --dry-run                 # 先看计划，不写文件
motrix-cli-skill install --skill motrix-cli-en     # 只装英文版
motrix-cli-skill path                              # 安装位置 + 版本 + 是否健康
motrix-cli-skill doctor                            # 体检：Node / CLI / bridge / skill 完整性
motrix-cli-skill doctor --json                     # 给脚本消费
motrix-cli-skill uninstall --dry-run
motrix-cli-skill uninstall                         # 只删自己写的文件
```

退出码：`0` 正常；`1` 有需要处理的问题（`doctor` 检查未通过，或安装目标不可写）；
`2` 用法错误；`3` 非预期错误。

### 目标目录属于别的用户时

典型场景：`~/.claude` 曾被 `sudo` 安装过，`~/.claude/skills` 属主是 root。这时安装会：

- 成功写入所有可写目标（例如 `~/.codex/skills`），
- 对不可写目标报出 `EACCES` 与属主，并提示可选项（只用 `--target codex`、自行修正该目录属主、
  或改用你拥有的目录），**不会用 `sudo` 去绕过**，
- 以退出码 `1` 结束，表示"有需要处理的问题"。

### 目录被占用时

如果 `~/.codex/skills/motrix-cli` 已存在且**不是**本包安装的（没有清单），安装会拒绝并报
`not managed by motrix-cli-skill`。确认要接管时显式加 `--force`；否则先自行处理该目录。

### 卸载行为

只删除清单里记录的文件，然后清掉空目录。若你在该目录里放了别的文件（例如 `notes.md`），
目录会保留、文件不动。`uninstall` 不会碰官方的 `~/.codex/skills/motrix`。

## 5. doctor 输出怎么看

```text
✓ node 24.20.0 (>= 22 required)
✓ motrix CLI 0.5.0 at /Users/<you>/.local/bin/motrix
✓ bridge reachable at http://127.0.0.1:16802 (state: ready, aria2 1.37.0-motrix.16, 10 features)
✓ paired endpoints file (1 paired)
✓ skill motrix-cli [codex] v0.1.0
```

| 行 | 不通过时的处理 |
| --- | --- |
| `node` | 升级 Node 到 22+ |
| `motrix CLI` | `npm i -g @motrix/cli`，检查 PATH 与安装 prefix 下的 `bin` |
| `bridge unreachable` | 本地 `motrix open`；远端检查 `--endpoint`/网络；鉴权类错误重新 `motrix pair` |
| `paired endpoints file` | 未配对远端时属正常（本地桌面版不需要配对） |
| `skill ...`（未安装） | 提示性信息：只在你需要该 agent 时才要装。退出码不受影响 |
| `skill ...`（已安装但不健康） | 重新 `motrix-cli-skill install` 覆盖修复；版本不一致时同理会重装为新版本 |

`doctor` 与 `mdxp.mjs endpoints` 都**不会打印 token**，只报告是否已配对。

退出码 `1` 的判定条件是：Node 版本、`motrix` CLI、bridge 可达性、以及「至少装了一处且每处都完整」。
因此像 `~/.claude/skills` 属主是 root 而你只用 Codex 这种情况，只会在列表里以 `-` 提示，不会让
`doctor` 一直报红。

## 6. agent 侧怎么用

装好后 agent 通过 skill 里的两条路径工作：

```bash
# 常规操作：官方 CLI（退出码语义完整）
motrix list --status downloading --json | jq -r '.tasks[] | .id'
motrix add "https://example.com/f.zip" --save-dir ~/Downloads
motrix watch --task <taskId>

# CLI 没有子命令的方法：skill 自带脚本（默认只读）
node ~/.codex/skills/motrix-cli/scripts/mdxp.mjs engine/status
node ~/.codex/skills/motrix-cli/scripts/mdxp.mjs task/get --task <taskId>
```

原生脚本的 token 解析顺序与 CLI 一致：`--endpoint`/`--token` → `MOTRIX_BRIDGE_TOKEN` →
本地 `endpoint.json` → 已配对凭据；没有 token 时 bridge 返回 HTTP 401。

## 7. 升级与回滚

```bash
npm i -g motrix-cli-skill@latest    # 升级（全局安装会重新写入 skill 文件）
motrix-cli-skill doctor             # 确认版本与完整性
motrix-cli-skill uninstall --target all --skill all
```

升级 `@motrix/cli` 之后，如果需要刷新 skill 内的 schema 快照，见《发布.md》第 6 节。
