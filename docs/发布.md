# 发布流程

包名 `motrix-cli-skill`（unscoped，public），仓库 `vorekkk/motrix-cli-skill`。

## 1. 发布前检查

```bash
npm test              # 50 个用例，全部应通过
npm run pack:check    # 确认两个 skill、bin、src 都在产物里，且没有 test/ 与 .github/
```

`pack:check` 会打印 `npm publish` 实际会带上哪些文件。当前产物为 17 个文件、约 170 KB。

## 2. 首版发布（必须手工一次）

npm 的可信发布（Trusted Publishing）配置在**包的设置页**上，所以包必须先存在：

```bash
npm login            # 用有发布权限的账号登录（或配置 granular token 到 _authToken）
npm whoami
npm publish --access public
npm view motrix-cli-skill version
```

发布后做一次干净安装复验：

```bash
clean_prefix=$(mktemp -d)
npm i -g motrix-cli-skill --prefix "$clean_prefix"
"$clean_prefix/bin/motrix-cli-skill" --version
rm -rf "$clean_prefix"
```

## 3. 配置 OIDC 可信发布（首版之后）

在 <https://www.npmjs.com/package/motrix-cli-skill/access> 的 **Trusted Publisher** 区域选择
GitHub Actions，并填写：

| 字段 | 值 |
| --- | --- |
| Organization or user | `vorekkk` |
| Repository | `motrix-cli-skill` |
| Workflow filename | `release.yml` |
| Environment name | `npm` |

同时在 GitHub 仓库创建 Environment `npm`（可选加保护规则）。`release.yml` 已按此配置写死：
`id-token: write` + `environment: npm` + `npm publish --provenance --access public`，
**仓库里不存任何 npm token**。

可信发布要求 npm CLI ≥ 11.5.1 且 Node ≥ 22.14；workflow 使用 Node 24（自带 npm 11.x）。

## 4. 日常发版

```bash
npm test && npm run pack:check
git add -A && git commit -m "chore: release v0.1.1"
npm version patch          # 生成 v0.1.1 提交 + tag
git push --follow-tags
```

推送 `v*` tag 会触发 `release.yml`：

1. `verify`：跑测试、校验产物、校验 tag 与 `package.json` 版本一致、打包并上传 artifact。
2. `publish`：仅在 tag 场景执行，用 OIDC 以 `--provenance` 发布。

手工触发 `workflow_dispatch` 时 `dry_run` 默认为 `true`（只验证、不发布）。

## 5. 发布失败怎么处理

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `403 Forbidden` / `ENEEDAUTH` | 未登录或没有该包权限 | 本地 `npm login` 后重试；CI 场景检查 trusted publisher 配置 |
| `EPUBLISHCONFLICT` / 版本已存在 | npm 版本号不可复用 | `npm version patch` 后重新打 tag |
| tag 校验失败 | tag 与 `package.json` 版本不一致 | `git tag -d <tag>` + `git push --delete origin <tag>` 后重打 |
| provenance 报错 | 缺少 `id-token: write`，或不在 GitHub 托管 runner 上 | 检查 `release.yml` 的权限与 environment 名 |

## 6. 升级 @motrix/cli 后刷新 schema 快照

skill 内的 `reference/mdxp-catalog.json` 来自 `motrix describe --json`：

```bash
npm i -g @motrix/cli@latest
npm run sync:catalog     # 重新生成两份快照（确定性输出，无时间戳）
npm test                 # 校验快照一致且覆盖 8 个方法
git add -A && git commit -m "chore: refresh MDXP catalog snapshot"
npm version patch && git push --follow-tags
```

快照仅用于离线阅读，**权威来源始终是 `motrix describe --json`**。若 CLI 落后于目标 Motrix
（出现 `-32601` 或 HTTP 404），应先升级 CLI。
